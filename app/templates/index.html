Backup of ColdVault's own data

The index — checksums verified at upload, manifest results, sessions, restores, deletion records and settings — exists only in ColdVault's database; S3 can't give it back. ColdVault writes a consistent snapshot of it (plus CSV copies, logs and the non-secret config) to latest/ in the backup folder. Point rsync, borg or restic at that folder, not at the live data/coldvault.db, which can be caught half-written.

Using it with rsync / borg / restic
The folder is ./backups next to docker-compose.yml unless you mounted another one at /backups. To make sure your tool never runs halfway through a snapshot, have it ask for a fresh one first. The call returns only when the snapshot is finished and fails if it didn't work: 
curl -fsS -X POST http://localhost:9999/api/backup \
  && restic -r /mnt/nas/restic backup ~/coldvault/backups/latest
Or just schedule your tool for after the daily time above. Files are left uncompressed so borg/restic can deduplicate between runs. To restore: stop ColdVault, copy latest/coldvault.db into the data folder, start it. Credentials are never included, so back up your .env separately.

Email notifications

Configure RESEND_API_KEY, COLDVAULT_EMAIL_FROM and COLDVAULT_EMAIL_TO in .env. With COLDVAULT_NOTIFY=true, every canary upload is followed by an audit and a report email automatically. The sender must be on a domain verified in your Resend account (or use onboarding@resend.dev to test).
